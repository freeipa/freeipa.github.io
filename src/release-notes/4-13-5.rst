.. _highlights_in_4.13.5:

Highlights in 4.13.5
--------------------

* CVE-2026-53683: Client-side open redirect in reset_password.html

`reset_password.html` page parses query string parameters and uses url as a
redirection target (window.location = url) after password reset, optionally
delayed by delay. No validation or allowlisting is performed on url, enabling
an attacker to redirect users to an arbitrary external site after completion of
the workflow.

An attacker must entice a victim to use the crafted reset URL (not hard, as the
URL domain appears legitimate). No attacker authentication is required. The
redirect can be used for phishing and user-trust abuse (appearing to originate
from IdM), and can assist chaining with other social engineering or browser
attacks by moving users from a trusted IdM origin to an attacker-controlled
site at a sensitive moment. Ultimately, the attacker can get a user to visit a
malicious URL while appearing legitimate.

* CVE-2026-86593: Unauthenticated DoS in session endpoints (login_password, change_password, sync_token) via Unbounded Request Body Read

The public session endpoints `login_password`, `change_password`, and
`sync_token` do not limit unauthenticated attacker from causing additional load
on WSGI processes and may lead to denial of service situations. Because that
worker pool is shared by the whole `/ipa` WSGI application, exhausting it
denies all IPA HTTP functionality, including the GSSAPI/Kerberos-authenticated
paths (WebUI, admin RPC), not only other unauthenticated requests.

This is a distinct instance of the same root-cause class already fixed for
`i18n_messages` (CVE-2026-73198) and `/ipa/migration/migration.py`
(CVE-2026-73197); the fix for CVE-2026-73198 was scoped only to a single
caller and left this defect present in the three session endpoints.
